# Іпсомнія · Архітектура

> **EN summary.** Ipsomnia is a browser game that trains people to recognise and counter hostile information operations. It is dependency-free vanilla JS with no build step. The one design rule that everything else follows: **content is data, the engine is generic.** A new operation is a new object in `content.js`; `engine.js` does not change. This document walks through the runtime flow, the game economy, the file layout and where to look in the code.

## 1. Що це

Гейміфікований тренажер інфостійкості. Гравець проходить операції на мапі України:
знаходить у стрічці ворожі пости, визначає техніку маніпуляції, обирає контрхід на
таймері та отримує розбір. Методологічна основа: inoculation theory (ідея, що
«щеплення» ослабленою дозою маніпуляції робить людину стійкішою до справжньої).

Продакшн: <https://ipsomnia.com/>

## 2. Головний принцип: контент окремо від двигуна

```
content.js   →   дані: SCENARIOS, ROLES, WILD, mapOps, діалоги, туторіал (UK + EN)
engine.js    →   логіка: стан, фази, таймери, HUD, рендер екранів
index.html   →   розмітка, стилі, інтро-заставка
```

Двигун ніколи не знає, яку операцію він грає. Він читає масив `SCENARIOS` і
працює з полями об'єкта. Тому:

- нова операція = один новий об'єкт у `SCENARIOS_UK` і `SCENARIOS_EN`, нуль правок у двигуні;
- режим «Червона команда» (`creator.html`) збирає операцію за тією самою схемою і передає її
  посиланням `?pack=<base64>`, і двигун грає її без змін;
- повна схема об'єкта операції задокументована в хедері `content.js`.

## 3. Потік гри (runtime)

```
index.html завантажено
  └─ #ipso-boot (інтро-заставка, 1.4–3с) → подія 'ipso:intro-done'
       └─ engine.js: ipsoIntroDone()
            ├─ ?pack= у URL → bootPack() → бріфінг → операція → PvP-звіт
            └─ інакше → modeSelect()                     (екран режимів)
                 └─ startIntro()                         (катсцена з Інструктором, раз за сесію)
                      └─ roleSelect() → pickRole()       (роль = складність)
                           └─ campaignMap()              (хаб; операції відкриваються хвилями по 3)
                                └─ selectOp()
                                     ├─ бос → startBossIntro() (катсцена) → startScenario()
                                     └─ інакше → startScenario()  (бріфінг)
                                          └─ launchAttack()       (стартовий удар по стійкості)
                                               └─ phaseFeed()     ФАЗА 1 · розпізнай (+ OSINT 🔍)
                                                    └─ resolveFeed()
                                                         └─ [phaseSubQuestion()]  ФАЗА 1б, якщо є
                                                              └─ wildThen() → [showWild()]  несподівана подія
                                                                   └─ phaseTech()          ФАЗА 2 · техніка
                                                                        └─ [phaseAudience()] ФАЗА 3, якщо є
                                                                             └─ phaseCounter() ФАЗА 4 · контрхід на таймері
                                                                                  └─ phaseAAR()  розбір + ранг A/B/C
                                                                                       ├─ nextScenario() → campaignMap()
                                                                                       ├─ replayOp()     (відкат до знімка)
                                                                                       └─ бос → finale()
```

Кожен екран малюється через `render(html, glitch)`, який повністю підміняє вміст
`#app` і прибирає таймери, модалки та підказки попереднього екрана. Топбар (HUD) і
плаваючі кнопки живуть поза `#app` і переживають усі рендери.

## 4. Стан

Увесь стан кампанії лежить в одному об'єкті `S` (engine.js, секція 3), кожне поле
прокоментоване. Ключові величини:

| Поле | Що це |
|---|---|
| `S.infl` | **Стійкість** 4..100. Головна шкала. ≤8 в операції = поразка |
| `S.rep` | **Довіра** 0..100. <50 ріже гейни контрходів навпіл, <30 підсилює стартовий удар |
| `S.streak` | Серія чистих відповідей: ×1.5 від 3, ×2 від 5 |
| `S.cons` | Лічильник «гучного мовчання»; ≥2 на фіналі = кризова подія |
| `S._op`, `S._snap` | Підсумки поточної операції (для рангу/AAR) і знімок стану на її старті (для «перепройти») |

Поза `S` навмисно тримаються прапорці сесії, які «ЩЕ РАЗ» не скидає: `introSeen`,
`tutorialDone`, `hintsShown`. Прогрес на мапі (пройдені `id`) зберігається в
`localStorage`, тому переживає перезавантаження.

## 5. Економіка (баланс)

Усі зміни шкали проходять через три помічники: `clamp` (межі 4..100), `pen`
(штраф × коефіцієнт ролі), `gainAdj` (гейн × серія, /2 при низькій довірі).

| Подія | Стійкість | Довіра |
|---|---|---|
| Старт операції | −10…−14 (× роль); бос −18 | |
| Знайдений явний / тонкий наратив | +5 / +8 | |
| Пропуск | −6 | −1 (лише явний) |
| Хибна тривога | −6 | −2 |
| Техніка вірно / хибно | +7 / −8 | |
| Контрхід best / середній / шкідливий | +12 / +2…5 / −12 | +3 за best; поле `rep` опції |
| Таймер контрходу | −2 кожні 9с; на нулі «вакуум» −5 кожні 5с | −3 раз на нулі |

Ранг операції: 0 помилок A, 1 B, 2+ C (швидкість лише показується). Ранг кампанії за
стійкістю: ≥78 Інфостійкий, ≥52 Медіаграмотний, інакше Жертва методички.

## 6. Структура репозиторію

| Шлях | Що це |
|---|---|
| `index.html` | Точка входу: розмітка, стилі, інтро-заставка |
| `engine.js` | Двигун (12 секцій, хедер файлу = зміст) |
| `content.js` | Контент-пак UK + EN (хедер файлу = схема даних) |
| `design-tokens.css` | Палітра, свічення, CRT-оверлеї |
| `creator.html` | Режим «Червона команда»: конструктор операцій → `?pack=` |
| `validate.js` | Лінтер контенту перед деплоєм (`node validate.js`) |
| `qrcode.js` | Стороння бібліотека QR (MIT) для кріейтора |
| `assets/` | Ілюстрації, портрети, шрифти (`fonts/`), звуки (`sfx/`) |
| `archive/` | Перша однофайлова демка і лабораторія CRT-ефектів; у грі не використовуються |

## 7. Технічні рішення, які варто знати

- **Без білдів.** Файл відкривається подвійним кліком, працює офлайн, на телефоні й ноутбуці.
  Шрифти і звуки самохостяться; якщо файлів нема, гра працює мовчки без помилок.
- **Мобільний в'юпорт у пріоритеті.** Скрол живе в `#app`, не в `body` (обхід багів iOS Safari),
  тап-зони ≥48px, safe-area враховано.
- **Таймери від реального часу.** `startTimer` рахує залишок від `Date.now()`, а не декрементом,
  тому стійкий до тротлінгу фонової вкладки.
- **i18n без перезавантаження.** `applyLang()` у `content.js` перепризначає глобальні масиви,
  `setLang()` у двигуні перемальовує поточний екран через `currentScreen`; стан не губиться.
- **Звук через Web Audio** для коротких sfx (без затримки) і `<audio>` з кросфейдами для музики;
  автоплей знімається першим кліком.
- **Навчальне ядро.** Під час місії гравець бачить лише вердикт і перше речення пояснення;
  повний розбір кожної відповіді (`e`, `w`) чекає в After Action Report, щоб не ламати темп.
